# 门神 Menshen

**Telegram 群组反广告机器人。** AI 两级判定，先删后判，按「用户资历 × 置信度」
自动删除 / 禁言（可改为封禁），并定时把处置结果汇总私聊给管理员。

[![Go](https://img.shields.io/badge/Go-1.25-00ADD8?logo=go&logoColor=white)](go.mod)
[![Image](https://img.shields.io/badge/ghcr.io-x6nux%2Fmenshen-2496ED?logo=docker&logoColor=white)](https://github.com/x6nux/menshen/pkgs/container/menshen)
![CGO](https://img.shields.io/badge/CGO-free-brightgreen)

> 门神贴在门上挡邪祟。这个项目的两道主防线也都在门口 —— 冷判定拦进群、
> 联合封禁拦全平台，宁可不让他进来，也不等他进来发完再删。

纯 Go，无 CGO，单文件二进制 + 一个 SQLite 库。多租户：一个进程服务
任意多个 bot，各归各的管理员。

## 特性一览

- 🤖 **两级 AI 判定** —— 快模型初判抢时间，大模型复判定案；每级可配多个模型，重试时按顺序自动切换；判定失败一律放行，上游抖动不误伤。
- ⚡ **先删后判** —— 初判一出结论立即删消息、临时禁言 5 分钟，复判慢慢定案；判为正常则不再追加处置。
- 🎯 **按人分档处置** —— 新人（进群 < 72 小时或发言 < 10 条）从重，老人只删不禁；阈值逐群可调，禁言可整档改为永久封禁。
- 🧠 **闭环学习** —— 管理员一键标记误判 / 命中，样本沉淀为形态摘要，回注入此后每一条消息的判定，面板可直接编辑。
- 🚪 **进群冷判定** —— 本地预筛 + AI 画像，把引流号拦在进群那一刻；被限制者可人机验证后自助申诉。
- 🚫 **联合封禁** —— 一处判到最高档或被人工标记，全平台所有接入群一起封。
- 🔁 **内容哈希** —— 同一条广告换号再发不再花钱，直接删。
- 🖼 **识图** —— 配上视觉模型后，图片和贴纸一样判。
- 👥 **多租户** —— 主管理员管上游、模型与钱，次级管理员各接各的 bot、各管各的群。
- 🔧 **主 bot / 工作 bot 分离** —— 配置里的 bot 只管面板与接入，群内判定由面板接入的工作 bot 执行；主 bot 被拉进群会自动退出。
- 📊 **成本可见** —— 每条群消息都送检，面板实时显示近 24 小时的送检数与折算开销。
- 🚨 **上游异常告警** —— 连续多次请求失败后私聊管理员，提示检查渠道与密钥。
- 📝 **自助申诉** —— 被处罚的人可在私聊发起：AI 先复核，维持原判则走网页人机验证（Turnstile），通过后签发解禁码由管理员兑换；原文与理由改由签名查看页展示。
- 🖥 **Mini App 配置台** —— 点 bot 菜单里的「配置」在 Telegram 内打开完整配置界面（上游 / 模型 / 机器人 / 群组 / 参数 / 名单 / 记录），initData 验签鉴权。
- 🧪 **演练模式** —— 按群开关，判定照跑但不处置；新群先演练，校准阈值后再转正式。

## 它怎么工作

群消息（含编辑）先过守门与留底，再进两级 AI 判定，命中后按处置矩阵执行：

```text
群消息 → 守门（总开关 / 群白名单 / 豁免）→ 留底
      → 内容哈希命中？ → 直接删
      → 护栏（去重 / 限频，新人不受限）
      → [识图] → 初判 → 先删 + 临时禁言
      → 大模型复判 → 定案：禁言 / 封禁、连带删除、告警、流水
```

处置矩阵（阈值均可调）：

| 置信度 | 新人 | 老人 |
|---|---|---|
| ≥ 90% | 删除 + 禁言 + 告警 | 删除 + 告警 |
| 75% ~ 90% | 删除 + 告警 | 仅告警 |
| < 75% | 不处置 | 不处置 |

新人 = 进群 < 72 小时 **或** 群内发言 < 10 条。禁言那一档可改为
**永久封禁出群**，bot 级给默认、每个群单独选；「仅删除」的档位可另配一记
**5 分钟短禁言**（`antiad_short_mute`，默认关），堵住删完就接着发的空档。

> 老人永远不自动禁言：误伤一个长期成员的社交代价远大于漏一条广告，
> 告警里给管理员一键补刀的按钮就够了。

完整判定规则（内容哈希、规避形态、冷判定、护栏）见
**[判定链路](docs/how-it-works.md)**。

## 快速开始

### Docker（推荐）

```bash
git clone https://github.com/x6nux/menshen.git && cd menshen
cp config.example.yaml config.yaml   # 填 bot_token 与 admin_ids
docker compose up -d
```

也可以直接用发布好的镜像（amd64 / arm64）：把 `docker-compose.yml` 里的
`build: .` 换成 `image: ghcr.io/x6nux/menshen:latest`（或钉一个版本号），
再 `docker compose up -d`。

### 单文件二进制

```bash
CGO_ENABLED=0 go build -o menshen .
./menshen -config config.yaml
```

配置文件不是必需的：每一项都支持 `MENSHEN_*` 环境变量覆盖，
详见 [config.example.yaml](config.example.yaml)。

### 第一次使用

配置文件里的 bot 是**主 bot**：只做配置管理，不入群、不判定。私聊 bot 发 `/start` 打开管理面板（或点菜单按钮「配置」打开 Mini App），按提示走：

1. **🔌 上游渠道** — 加至少一个 AI 上游（base_url + api_key）
2. **🤖 模型定价** — 按 `上游名/模型ID` 录入模型与单价（只用于把开销折算成钱）
3. **⚙️ 全局设置** — 选默认判定模型，打开总开关
4. **🤖 我的机器人** — 接入一个**工作 bot**（判定由它执行，需要 webhook 模式）
5. 把**工作 bot** 拉进群并**设为管理员**（删除消息 + 封禁用户权限），再为它添加该群的 `chat_id`
6. 观察几天演练结果，校准阈值后切正式模式

面板会逐条点名还缺什么配置 —— 判定链路有四个前置条件，缺任何一个都表现为
「一条都没拦到」而不报错，别忽略那段提示。

> **主 bot 与工作 bot**：主 bot 只做配置管理与接入其他 bot，被拉进群或频道
> 会自动退出。判定必须有 webhook 模式 —— 长轮询模式下只有主 bot 能收更新，
> 而主 bot 不判定。

## 使用

### 群内命令

| 命令 | 作用 | 权限 |
|---|---|---|
| `/check` | 复查某人是否在发广告：把该用户在本群的全部留底交给两个模型互相印证 | 所有人 |
| `/ban` | 人工直接标记为广告，跳过 AI 按最高档处置并进联合封禁 | 群管理员及以上 |
| `/white` | 加入本群反广告白名单（频道填 `-100` 开头的 ID） | 群管理员及以上 |
| `/log <id>` | 查看某条判定记录卡片（管理员私聊；卡片上可处置） | 管理员 |
| `/user <uid>` | 查看某人的判定记录列表，每条可点开处置 | 管理员 |

都支持回复对方消息发，或直接带 `<user_id>` 参数。非授权者发 `/ban` / `/white`
会被**静默忽略** —— 回一句「你没有权限」等于告诉刷屏的人这条命令值得去试。

### 通知

- **群内展示**（每群开关，默认关）：逐条贴处置结果与按钮，按人节流，到点自动撤回。
- **私聊汇总**（默认开）：命中、判定失败、复判为正常汇成一条，默认每 5 分钟最多一条；
  点「📋 #编号」进记录卡片处置，「↩️ 误判」一键纠正。

### 管理面板

上游与模型、接入 bot、群配置、阈值、账本与开销都在私聊面板里以按钮完成，
不需要额外的 Web 后台。接入新 bot 只需把 BotFather 给的 token 发给面板
—— 本服务自动验证、起实例、注册回调，你发的那条含 token 的消息**会被自动删掉**。

多租户权限划分与面板全貌见 **[面板与租户](docs/panel.md)**。

## ⚠️ 部署前必读：三个静默失效点

1. **bot 不是群管理员 = 一条普通群消息都收不到。**
   Telegram 的 privacy mode 默认只把命令和回复推给 bot。此时面板一切正常、
   日志干净、什么都没判。兜底是反广告面板上每个生效群后面的自检标记
   （✅ 权限正常 / ⚠️ bot 非管理员）。
   privacy 是在 bot 入群时定下的：在 BotFather 里改完必须**把 bot 移出群
   再重新加**。

2. **`allowed_updates` 一旦显式声明，Telegram 的默认清单就整体失效。**
   所以 `message` / `edited_message` / `callback_query` 也必须原样列在里面，
   删掉哪个哪个就彻底收不到，而 getUpdates / setWebhook 都不会因此报任何错。

3. **判定链路有四个前置条件，缺任何一个都表现为「一条都没拦到」而不报错。**
   主菜单会逐条点名还缺什么，别忽略那段提示。

## 成本

**每条群消息都送检**，这是设计如此，不做抽样。面板上「近 24 小时」那行
实时摆着送检数与折算开销 —— 这是这个功能最大的风险点，所以放在最显眼处。

护栏（都可调）只堵滥用，不改「每条都判」的设计：同一条消息只判一次、
每群每分钟送检上限（新人不受限）、同一人告警节流、`/check` 按人限频。
内容哈希让同一段广告模板被多号轮番刷时，后来者不再花钱。
