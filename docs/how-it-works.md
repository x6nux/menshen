# 判定链路

门神怎么判、怎么罚、怎么学。只想知道怎么装怎么用，看 [README](../README.md)。

## 总览

```
群消息（含编辑）→ 守门（总开关/群白名单/豁免）→ 留底
      → 内容哈希命中？→ 直接删，禁言交给复判模型
      → 护栏（按消息去重/每群频率，新人不受限）
      → [识图] → systemone 初判 → 先删 + 临时禁言 2 分钟
      → 低置信或要罚时大模型复判 → 定案：正式禁言/封禁、连带删除、告警、流水
```

两级判定共用同一份送检载荷，看到的信息完全一致。**判定失败一律放行** ——
反过来会在上游抖动时清空整个群聊。

网络抖动与 5xx/429 会自动重试（最多 5 次，指数退避）：判定与复判各自可以
配置**多个模型**，第 n 次尝试用列表里的第 n 个 —— 顺序即重试顺序，模型各自
绑定自己的上游。4xx 是配置问题，同一个模型不再重试，但列表里还有没试过的
模型时会换下一个。主判模型报错时不空等，当场落到复判模型 —— 有一个能答上来
就不该放行。

## 模型与上游

模型名统一写成 `<上游名>/<模型ID>`（如 `zhizengzeng/gpt-5-mini`、
`openrouter/openai/gpt-4o`）：前缀决定这个模型走哪个上游，按**第一个** `/`
切分，所以上游名不能含 `/`。旧格式（无前缀）继续兼容，会任选一个可用上游。

模型列表在面板里用逗号分隔、按重试顺序排列。同一个上游想多试几次，把它
写进列表多次即可。上游改名会连带改写所有引用；名下有模型时不能删除上游。

只有一个上游时，启动会把旧格式模型自动补上前缀（无歧义）；有多个上游时
不动数据，面板上会提示重新按前缀添加。

连续多次请求失败（默认 5 次，可调）会私聊 bot 归属人与主管理员，提示检查
该上游的渠道、密钥与余额；告警有冷却（默认 30 分钟），成功一次即清零计数。

## 处置矩阵

阈值均可调：

| 置信度 | 新人 | 老人 |
|---|---|---|
| ≥ 90% | 删除 + 禁言 + 告警 | 删除 + 告警 |
| 75% ~ 90% | 删除 + 告警 | 仅告警 |
| < 75% | 不处置 | 不处置 |

新人 = 进群 < 72 小时 **或** 群内发言 < 10 条（潜伏号）。
禁言那一档可以改成**永久封禁出群**：bot 级「禁言改为封禁」给默认，
每个群可以单独选「跟随 / 禁言 / 封禁」。

**老人永远不自动禁言**：误伤一个长期成员的社交代价远大于漏一条广告，
告警里给管理员一键补刀的按钮就够了。

## 先删后判

初判一出结论就先删、该罚的先临时禁言 2 分钟，再慢慢等大模型复判定案。
复判判为正常就不再追加处置（临时禁言到点自然解除），私聊汇总里
以「↩️ 复判为正常」列出，删掉的消息回不来，留给你事后看一眼。

## 删多少

只是这条消息是广告就删这一条（相册整组删）；账号本身就是广告号
（用户名/昵称/简介写着广告，或挂的频道本身是广告）且新人过删除+禁言线时，
连带删掉此人近 48 小时在本群的全部消息。

## 内容哈希

判成「消息本身就是广告」并删掉的内容会记下指纹，同样的内容
（空白差异忽略）再出现时不送检、直接删，禁不禁言交给复判模型。只记消息级
广告、只在正式群里记、按 bot 隔离；点「↩️ 误判」或复判判为正常会撤掉。

## 规避形态

编辑成广告会重新送检；以频道身份发言按频道论处（封频道）；
访客 bot 代发的算在召唤者头上；简介里挂的频道/群组会被查清是什么
（挂自己的技术频道不算广告）；配了识图模型后图片与贴纸也判。

## 演练模式

按群设：判定照跑、开销照花，但不删不禁言，只报告「本应执行什么」。
新加的群先演练、老群已正式是最常见的需求，所以它落在每个群上
而不是全局一刀切。

## 进群冷判定

默认关，开关在**全局设置**里配一次，所有 bot 默认跟随；单个 bot 可在参数页
覆盖（列表里带 ✏️），填 `-` 撤销覆盖、继续跟随全局。

开启后，进群时本地预筛筛出昵称或简介里带引流话术的账号，只把这些送 AI
判画像，命中即限制发言并给出具体原因。被限制的人可以在群里点按钮、
私聊完成人机验证后自助申请复核 —— 改对了当场解除。

## 联合封禁

默认关。一处判到最高档或被人工标记，全平台所有接入群一起封，并拦在进群
那一刻。解除时走 `only_if_banned`，不会把没被封的人反而踢出群。

## 闭环学习

管理员在告警上点「↩️ 误判」，该样本进反例池；确认命中的进正例池；
`/adb` 的人工标记结果也进正例池，是质量最高的训练样本。

积累够数后自动总结成一段形态摘要，回注入此后每一条消息的判定。
摘要可在面板上直接编辑 —— AI 写歪时不必等下一轮覆盖。
摘要会乘以每一条群消息的成本，面板上明码标价了它折合多少 token。

## 成本与护栏

**每条群消息都送检**，这是设计如此，不做抽样。面板上「近 24 小时」那行
实时摆着送检数与折算开销 —— 这是这个功能最大的风险点，所以放在最显眼处。

护栏（都可调）：同一条消息只判一次、每群每分钟送检上限（只管老成员，
新人不占额度）、同一人告警节流、`/ad` 按人限频。它们只堵滥用，不改
「每条都判」的设计。超出上限没送检的记成「⏭ 未送检」，面板上看得见。
同一段广告模板被多号轮番刷时，内容哈希让后来者不再花钱。
