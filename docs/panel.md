# 面板、命令与通知

## 管理面板

私聊 bot 发 `/start` 就是管理面板。主菜单按角色决定露出哪些入口：

- **🤖 我的机器人** —— 接入新 bot、管理生效群、逐群配置阈值与行为
- **👥 管理员**（主管理员）—— 添加次级管理员，配额 `max_bots_per_admin`
- **🚫 联合封禁**（主管理员）—— 全平台封禁开关与名单
- **🔌 上游渠道**（主管理员）—— AI 上游列表：名称、渠道类型（OpenAI Completions / Responses、Anthropic、Gemini、Cloudflare）、base_url + api_key；详情页可「测试连通」
- **🤖 模型定价**（主管理员）—— 按 `上游名/模型ID` 录入模型与单价，用于把开销折算成钱；判定 / 复判模型在「全局设置」里按重试顺序填列表
- **⚙️ 全局设置**（主管理员）—— 默认判定模型、总开关、私聊汇总间隔等

「🙈 豁免用户」页同时列出解禁码 / `/white` 产生的**白名单**行（范围、来源、
到期时间），可逐条移除。

面板上的请求都走按钮，由 bot 私聊完成，不需要额外的 Web 后台。

**接入一个 bot**：面板上点「➕ 接入新机器人」，把 BotFather 给的 token 发过来
就行。本服务会自动验证它、取回 bot 的身份、起实例并注册回调地址，全过程
在一条消息里实时汇报。你发的那条含 token 的消息**会被自动删掉** —— token
等同于该 bot 的完整控制权，不该留在聊天记录里。

配置文件里那个 bot 是**主 bot**：只做配置管理 + 接入其他 bot，不入群、
不判定广告，被拉进群或频道会自动退出。它的详情页是只读的，也不能停用或
移除。群里干活的是面板上接入的**工作 bot**。

## Mini App

管理员私聊里的菜单按钮「配置」打开 **Mini App**（`<public_url>/miniapp`，
仅 webhook 模式）。前端是独立的 React + MUI 工程（`web/`），由 Go 托管，
手机上就能完成全部配置。底部 5 个 Tab：

| Tab | 内容 |
|---|---|
| 概览 | 工作台：待办（未结申诉 / 演练中的群 / 停用的机器人，点击直达对应列表）、近 24 小时指标、最近命中、机器人运行状态 |
| 机器人 | 列表与详情：启用开关、归属改派、判定模型、逐项参数覆盖（只显示已覆盖项，智能控件编辑，可一键恢复全局） |
| 群组 | 搜索、按 bot 过滤、批量启停 / 切换演练 / 改处罚方式；群详情与添加群 |
| 记录 | 分段「判定记录 / 申诉」（申诉带未结角标）：搜索、筛选、无限加载；判定详情可 AI 复查 / 解封 / 加白 / 人工标记（主管理员另有联合封禁、解除，以及「AI 写规则」——针对本条记录跑规则发现）；用户资料页 |
| 我的 | 身份与权限摘要；名单管理（分段：白名单 / 资料放行 / 联合封禁 / 次级管理员）；上游渠道（详情页可「测试连通」）、模型定价、全局设置；主管理员另有 **AI 必封规则** |

**AI 必封规则**（我的 → AI 必封规则，仅主管理员）：一个 Eino 驱动的 Agent 从历史封禁
流水里自行探索，**一轮尽可能把所有未覆盖形态一次覆盖完**：启动消息里预取一份
`list_uncovered` 覆盖空白清单，Agent 按 `by_kind` 的空白从大到小逐类型处理，
每个类型按 `read_records`（一次最多 10 条完整正文）→ `find` 试跑 → `test_rule`
全库验证 → `create_rule` 的流程提交正则；创建后继续下一个类型，**每个未覆盖类型都要
有结论**（创建了规则，或说明为什么做不了），直到清完清单或跑满预算（单轮上限
**1000 步 / 30 分钟**，不设条数上限，运行中可随时停止）。**全库测试出现任何疑似误封
（clean/none/已撤销）就拒绝创建**并回传误封样本让它改进。**创建时若全库测试无误封会
自动启用（命中只作为判定证据），但不会自动开启强制**；页面能看到 Agent 运行状态与
最终结果、当前所有规则、以及任一规则跑全库的命中/命中广告/疑似误封样本。复核后手动
开启「强制」：命中即最高档处置（不花 AI），前提是这条 pattern 的全库测试零误封且已
测试过；否则命中只作为证据注入判定 prompt。白名单与管理员豁免在规则之前生效，
演练群只落流水。

两个入口：规则页的「开始发现」（全库模式），以及**记录详情页的「AI 写规则」**——
指定一条已确认、未撤销的判定记录，Agent 会围绕它的原文写正则，同时照常用 `find` /
`list_uncovered` 搜索同类形态，避免只针对孤例。运行状态里会显示正在针对的记录号。
「全局设置 → 总开关 → AI 规则发现自动运行」打开后**每小时最多自动跑一轮**：只有出现
现有规则覆盖不到的新广告（游标之后）才真正启动；新广告都已被覆盖时只推进游标，不花
模型钱。开关默认关，升级不会自动开始跑（一轮可能持续几十分钟、反复调模型）。

`find` 与 `test_rule` 都会返回**覆盖率**（该正则命中的已确认广告 ÷ 扫描窗口内全部已确认
广告）与按 `ad_kind` 的细分；覆盖率只作参考、不是创建门槛（创建仍只卡 fp/undone=0），
但优先覆盖占比大的形态。列表与规则详情会展示最近一轮测试的覆盖率；规则页的
**「测试正则」抽屉**可以输入任意正则试跑（不落库、不产生规则），展示命中统计、覆盖率、
按类型细分与样本，并可一键「用此正则新建规则」。规则列表支持**搜索**（名称/正则）、
**按状态筛选**（全部/启用/候选/强制）与**排序**（默认/覆盖率/命中广告/规则命中/最近创建）。

Agent 默认复用「默认模型 → 复判模型」列表里第一个 OpenAI 兼容模型；也可以在
「全局设置 → 默认模型 → 规则发现模型」里指定（形如 `上游名/模型ID`，留空 = 用回退
模型）。指定的模型必须已登记且启用，绑定的上游已启用、开启 chat 且是 OpenAI 兼容
渠道，否则启动时直接返回中文错误并指到这个设置项。

- **设置智能控件**：`0/1` 用开关、有界整数用步进器、时长给预设档位并显示
  换算（档位按 `min/max` 过滤），每张主题卡显示「已设置 N 项」摘要。
- **上游连通性测试**：用该上游已登记的模型发一次最小请求，行内显示延迟，
  失败给出可操作的错误文案。

鉴权用 Telegram WebApp 的 `initData`（HMAC 验签 + 24 小时有效期），
权限与面板一致：主管理员全通，次级管理员只能碰自己名下的 bot。
前端只做可见性收敛（如下表），服务端仍是唯一裁决：

**网页版（浏览器打开）**：私聊面板里的「🖥 网页版（浏览器打开）」按钮会发一条
签名登录链接（10 分钟有效，签名密钥与申诉/查看页共用 `web_secret`，轮换即全部
失效）。打开后种 HttpOnly 会话 cookie（12 小时，SameSite=Lax），API 请求带
`X-Web: 1` 头切换鉴权路径（自定义头触发 CORS 预检，跨站请求发不出来）。
宽屏自动切换**桌面外壳**：左侧固定导航（概览 / 机器人 / 群组 / 记录 / 我的，
主管理员另有名单 / 上游 / 模型 / AI 必封规则 / 全局设置直达），内容区限宽
1280px；窄屏浏览器自动退回移动端布局。会话过期时页面提示回 Telegram 重新
获取链接。

**公开网页**（申诉验证 `_w/ap`、原文查看 `_w/v`、申诉详情 `_w/apv`）同样是
React + MUI：无 Telegram SDK、无内联脚本，页面壳由 Go 托管，数据走同路径的
`?json=1` 与 POST；CSP 为 `default-src 'none'` + 同源脚本 + Turnstile 白名单
（无需 nonce）。

| 入口 | 主管理员 | 次级管理员 |
|---|---|---|
| 概览 / 机器人 / 群组 / 记录（含申诉） | ✅ | ✅（仅自己名下 bot） |
| 我的 → 名单 → 联合封禁（专属组 + 全局组） | ✅ | ✅ |
| 我的 → 名单 → 白名单 / 资料放行 / 次级管理员 | ✅ | ❌ |
| 我的 → 上游渠道 / 模型定价 / 全局设置 | ✅ | ❌ |

## 多租户
主管理员掌握上游、模型与联合封禁 —— 也就是掌握钱。他可以添加**次级
管理员**，次管各自接入自己的 bot、管自己那些 bot 在各群的行为与判定阈值。

| | 主管理员 | 次级管理员 |
|---|---|---|
| 上游渠道 / 模型定价 | ✅ | ❌ |
| 判定模型 | 全局默认 + 为单个 bot 覆盖 | ❌ 由主管配 |
| 接入 bot | 全部 | 只限自己名下（配额 `max_bots_per_admin`） |
| 群配置 / 阈值 / 流水 | 全部 | 只限自己 bot 名下 |
| 联合封禁开关与名单 | ✅ | ❌ |

主管理员名单只存在于配置文件里，不进数据库 —— 面板上删不掉它。

## 群内命令

全部支持回复对方消息发，或直接带 `<user_id>` 参数。群里 TG 客户端会自动补
`@botname`，两种形态都认得。

| 命令 | 作用 | 权限 |
|---|---|---|
| `/check` | 复查某人是否在发广告：把该用户在本群的**全部留底**一次性交给两个模型，两方结论互相印证后走同一套处置矩阵 | 所有人 |
| `/ban` | **纯封禁**：把此人封禁出群并留一条可撤销的处罚记录；不删发言、不进样本池、不进联合封禁 | 群管理员及以上 |
| `/banad` | **人工直接标记为广告**：不经过 AI，按最高档处置（删除 + 禁言/封禁）并进联合封禁名单 | 群管理员及以上 |
| `/uad` | 解除此人在本群的禁言/封禁、清掉处罚记录并给 24 小时白名单缓冲；本群生效的联合封禁一并解除 | 群管理员及以上 |
| `/ungban` | 只解联合封禁（不动别的处罚）：群管理员解除本群所属的专属组；主/次管理员连全局组一起解除 | 群管理员及以上 |
| `/white` | 加入本群反广告白名单（频道填 `-100` 开头的 ID）；**私聊里是加入本 bot 的豁免名单** | 群管理员及以上 / 管理员私聊 |
| `/jtime` | 查看入群时间：回复消息、带 `<user_id>`，或直接发（查自己）；库里没有时会实时回查 | 所有人 |
| `/log <id>` | 记录卡片：判定、处置、原文查看入口，卡片上可直接处置 | 管理员私聊 |
| `/user <uid>` | 此人的判定记录列表 + 生效中的限制与联合封禁（带解除按钮） | 管理员私聊 |

`/check` 对所有人开放：它不直接封禁，而群成员往往比管理员更早发现广告。
它同时是花钱与骚扰入口，靠 `antiad_cmd_rpm` 按发起人限频。

`/ban`、`/banad`、`/uad`、`/ungban` 与 `/white` 限群管理员及以上
（群管 / bot 归属人 / 主管理员）。`/banad` 绕过判定直接删人禁言，
对全群开放等于把删消息的权力交给任何人。
非授权者**静默忽略** —— 回一句「你没有权限」等于告诉刷屏的人这条命令存在、
值得去试。

`/banad` 的标记结果进正例池，是质量最高的训练样本，形态摘要下一轮就能学到；
`/ban` 是治安动作，不喂样本也不联封 —— 要标记广告别用错。

解封类命令（`/uad`、`/ungban`，以及记录卡片上的「🔓 解封」）都会连带解除
**在本群生效的联合封禁**，免得解了限制、名单一发言又把人禁回去。范围按
身份分：主/次管理员连全局组一起解，群管理员只解本群所属的专属组。

## 通知

- **群内展示**（每群开关，默认关）：逐条贴处置结果与按钮，按人节流，
  到点自动撤回（撤回记在库里，重启不丢）。不带昵称与原文。
- **私聊汇总**（默认开）：命中、判定失败、复判为正常汇成一条，每隔
  「私聊汇总间隔」（默认 5 分钟）最多一条。点「📋 #编号」进记录卡片处置。

记录卡片上可以一键「↩️ 误判」—— 样本进反例池参与闭环学习，详见
[判定链路](how-it-works.md#闭环学习)。
